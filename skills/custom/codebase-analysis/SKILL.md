# Codebase Analysis Skill

## 使用场景
- 用户明确要求“代码库分析 / 仓库分析 / 架构体检 / 项目扫描”。
- 输入给出一个本地路径（如 `/workspace/deer-flow`）或可访问仓库目录。

## 固定工作流（必须按顺序执行）
1. **确认边界**：确认分析路径、语言栈、是否聚焦某模块。
2. **快速清单**：读取根目录关键文件（README、package/pyproject、配置文件）。
3. **结构扫描**：列出 2~3 层目录并识别核心模块。
4. **入口定位**：定位前后端主入口、路由入口、任务调度入口。
5. **依赖与构建**：识别运行方式、构建工具、核心依赖。
6. **质量与测试**：检查测试目录、lint/format、CI 线索。
7. **风险识别**：找出高风险点（耦合、可维护性、配置漂移、安全/稳定性）。
8. **改进建议**：按优先级给出可执行建议（P0/P1/P2）。
9. **输出报告**：使用“固定十段式模板”。
10. **下一步行动**：给出 3 条可立即执行动作。

## 固定十段式报告模板（严格输出 10 段）
1. **分析范围与假设**
2. **项目概览（业务与技术）**
3. **目录结构与模块职责**
4. **关键执行链路（请求/任务/数据流）**
5. **依赖、配置与环境管理**
6. **代码质量与测试现状**
7. **可维护性与扩展性评估**
8. **风险清单（含影响与触发条件）**
9. **优先级改进建议（P0/P1/P2）**
10. **30 天落地计划（里程碑）**

## 注意事项规则
- 必须基于实际文件证据，不凭空臆测。
- 对不确定信息要明确标注“待确认”。
- 建议必须可执行，避免空泛表述。
- 若仓库过大，优先覆盖主链路并说明抽样范围。
- 输出语言默认中文；用户指定其他语言时遵从用户。
